Core Web Vitals a SEO: LCP, INP, CLS — co opravit jako první

Publikováno 22. 4. 2026 · ~10 minut čtení
technické seo optimalizace
Core Web Vitals jsou tři metriky Google (LCP, INP, CLS), které hodnotí rychlost načítání, odezvu při interakci a vizuální stabilitu stránky. Patří mezi ranking faktory, ale ne mezi ty nejvýznamnější — špatné hodnoty zřídka „potopí" web úplně, ale za jinak stejných podmínek má stránka s dobrými Core Web Vitals výhodu oproti konkurenci se špatnými. Pro většinu webů služeb přináší největší praktický efekt oprava LCP — nejvíc viditelné metriky pro uživatele.

Co jsou Core Web Vitals a jak souvisí se SEO

Core Web Vitals je sada tří metrik, které Google používá k hodnocení uživatelského zážitku z načítání a interakce se stránkou: Largest Contentful Paint (LCP), Interaction to Next Paint (INP) a Cumulative Layout Shift (CLS). Data se sbírají od skutečných uživatelů přes Chrome (zdroj se nazývá CrUX — Chrome User Experience Report), ne jen ze syntetických testů.

Pro SEO je to jeden z ranking faktorů v celkovém systému hodnocení stránky — vedle relevance obsahu, ne místo ní. Špatné hodnoty Core Web Vitals nevedou k automatickému vyloučení z výsledků vyhledávání, ale za jinak stejných podmínek (stejně relevantní obsah, podobná autorita webu) dá Google spíš přednost rychlejší a stabilnější stránce.

LCP — co zpomaluje a jak zrychlit

LCP (Largest Contentful Paint) měří čas, za který se načte největší viditelný prvek na obrazovce — obvykle je to hlavní obrázek, video nebo velký blok textu na začátku stránky.

Typické příčiny pomalého LCP:

  • Příliš těžké obrázky bez komprese a bez moderních formátů (WebP, AVIF).
  • Pomalá odezva serveru (Time to First Byte) — web na slabém hostingu dlouho začíná odesílat i první bajt dat.
  • Skripty a styly blokující rendering, které se načítají dřív než hlavní obsah.

Praktické kroky: zkomprimovat a správně naformátovat obrázky, zapnout cachování a případně připojit CDN, odložit načítání nekritických skriptů až po zobrazení hlavního obsahu.

INP (místo FID) — interaktivita

INP (Interaction to Next Paint) nahradil dřívější metriku FID a měří, jak rychle stránka reaguje na akce uživatele — kliknutí, stisknutí, zadávání textu — po celou dobu interakce se stránkou, ne jen při prvním kliknutí.

Pomalé INP nejčastěji souvisí s nadměrným množstvím JavaScriptu, který běží v hlavním vlákně prohlížeče a blokuje jeho reakci na akce uživatele. Odlehčení hlavního vlákna — rozdělení velkých skriptů na části, odložené načítání vedlejších funkcí — obvykle přináší největší efekt pro zlepšení této metriky.

CLS — posuny rozvržení

CLS (Cumulative Layout Shift) měří, jak silně prvky stránky „poskakují" během načítání — například když se text náhle posune dolů kvůli dodatečně načtenému obrázku nebo reklamnímu bloku bez předem vyhrazeného místa.

Časté příčiny: obrázky a videa bez explicitně uvedených rozměrů v kódu, dynamicky načítané bannery nebo widgety bez vyhrazeného prostoru, fonty způsobující posun textu při načítání. Řešení je ve většině případů technické: explicitně zadat rozměry pro obrázky, vkládané prvky a předem vyhradit místo pro dynamický obsah.

Co opravit jako první na typickém webu služeb

MetrikaOrientační hodnoty Google (dobré / špatné)Typická příčinaKdo opravuje
LCP≤ 2,5 s — dobré; > 4 s — špatnéTěžké obrázky, pomalý serverVývojář / poskytovatel hostingu

Pro typický web služeb je rozumné pořadí priorit: nejdřív LCP (nejvíc viditelný pro uživatele a nejčastěji nejsnáze vylepšitelný optimalizací obrázků a hostingu), poté CLS (obvykle se řeší cílenými úpravami vzhledu), a nakonec INP, pokud web nemá náročné interaktivní prvky jako složité filtry nebo kalkulačky.

Jak měřit

  • PageSpeed Insights. Bezplatný nástroj Google, který ukazuje jak laboratorní (syntetická) data, tak reálná data CrUX, pokud má web dostatek návštěvnosti pro jejich nahromáždění.
  • Google Search Console. Sekce „Základní webové signály" ukazuje data pro všechny stránky webu najednou, seskupené podle stavu (dobré, vyžaduje zlepšení, špatné).
  • CrUX (Chrome User Experience Report). Zdroj skutečných uživatelských dat, na jehož základě vznikají reporty v Search Console a PageSpeed Insights — dostupný i přímo přes samostatný dashboard pro podrobnější analýzu.

Časté otázky

Jsou Core Web Vitals oficiální ranking faktor Google?

Ano, Google oficiálně potvrzuje, že Core Web Vitals patří mezi ranking signály v rámci širšího systému hodnocení stránky, známého jako Page Experience. Přitom nejde o jediný ani nejvýznamnější faktor — relevance a kvalita obsahu i nadále hrají velkou roli.

Dá se Core Web Vitals na menším webu ignorovat?

Úplně ignorovat se nevyplácí, zejména pokud konkurence ve výsledcích vykazuje u těchto metrik dobré výsledky — v takovém případě se rozdíl v rychlosti může stát znatelnou výhodou. U velmi malého webu s nízkou konkurencí v oboru může být efekt zlepšení CWV méně výrazný než na konkurenčních trzích.

Jak Core Web Vitals souvisí s mobilní verzí webu?

Přímo: Google hodnotí Core Web Vitals v první řadě podle mobilní verze webu, v rámci mobile-first indexace. Pomalý mobilní web dostává horší hodnocení, i když desktopová verze funguje rychle.

Ovlivňují CDN a výběr hostingu v Česku tyto metriky?

Ano, doba odezvy serveru (ovlivňující LCP) přímo závisí na kvalitě hostingu a geografické blízkosti serveru k hlavnímu publiku webu. Připojení CDN pomáhá zrychlit doručování statických souborů (obrázků, skriptů, stylů) uživatelům v různých regionech.

Jak dlouho trvá oprava Core Web Vitals?

Bodové úpravy (komprese obrázků, zadání rozměrů pro média) mohou zabrat od několika hodin do několika dní práce vývojáře. Hlubší problémy — těžký JavaScript vyžadující refaktoring, nebo výměna hostingu — mohou zabrat několik týdnů, v závislosti na složitosti technické platformy webu.
